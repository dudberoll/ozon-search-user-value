# Ozon — E-CUP 2026, задача 3

## Цель

По истории активности в Поиске и Каталоге предсказать для каждого пользователя суммарную стоимость заказов (GMV) за следующие 30 дней. Целевой период в соревновании: 14 февраля — 15 марта 2026 года. Метрика — RMSLE, то есть ошибка считается по `log1p(GMV)`.

Данные разреженные: строки есть для дней с активностью. Не нужно создавать строки для каждого пользователя на каждый календарный день.

## Данные и файлы

- `train.parquet` — 30,631,006 строк, 18 полей; исторический период 1 января 2025 — 13 февраля 2026. Есть дневные признаки поиска, каталога, корзин, заказов и GMV.
- `sample_submit.csv` — корректный файл сабмита и наивный baseline: GMV за последний наблюдаемый 30-дневный период используется как прогноз на следующий месяц.
- `baseline-seacrh-ltv.ipynb` — обзор данных, генерация временных фолдов и baseline.

Файлы данных не входят в репозиторий. Для запуска положите `train.parquet` и `sample_submit.csv` в корень проекта; скрипт сохраняет результат в `catboost_predictions.csv`.

## Состояние baseline

Ноутбук строит признаки только из `gmv` и `searches` в трёх непересекающихся окнах по 30 дней (последние 30, предыдущие 30 и ещё предыдущие 30), используя `sum`, `max`, `std`, `mean`. Обучения модели и фактического расчёта RMSLE в нём пока нет.

Для временных фолдов ноутбук берёт шаг 14 дней при горизонте прогноза 30 дней, поэтому целевые периоды фолдов пересекаются. Для оценки моделей нужны фолды без пересечения целевых периодов. Путь в ноутбуке ожидает `data/train.parquet`, тогда как сейчас файл лежит рядом с ноутбуком.

## Следующий простой подход

Расширить агрегаты на корзины, заказы, GMV и конверсии отдельно для Поиска и Каталога; добавить давность последней активности и несколько временных окон. Сравнить наивный baseline с CatBoost-регрессией по `log1p(target)` на временной валидации без пересечения горизонтов и выбирать по RMSLE.
